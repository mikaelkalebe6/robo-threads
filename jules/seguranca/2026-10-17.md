# Relatório de Auditoria de Segurança

Este relatório apresenta a auditoria semanal de segurança realizada no repositório. O objetivo é avaliar os fluxos do GitHub Actions, scripts Python e arquivos de dados, comparando com o relatório anterior do dia 2026-10-10.

Conforme as premissas estabelecidas, considera-se já decidido que o repositório permanece privado, os valores de segredos são mascarados pelo GitHub Actions e as permissões de acesso são definidas por job.

## Comparativo com o Relatório Anterior e Evolução do Código

Desde o relatório de 2026-10-10, o código passou por melhorias importantes de segurança e organização.

Primeiramente, o envio da chave da API do Google no cabeçalho em requisições de download no arquivo `stitch.py` foi corrigido. Agora o cabeçalho de autenticação só é enviado quando o endereço de destino pertence ao domínio oficial do serviço.

Em segundo lugar, as regras de concorrência nos fluxos de automação do GitHub Actions foram configuradas nos arquivos `.github/workflows/artes-ia.yml` e `.github/workflows/robo.yml`. Isso impede execuções conflitantes durante atualizações simultâneas no repositório.

Além disso, foram adicionadas verificações automáticas antes do commit nos fluxos de automação. Essas checagens inspecionam os arquivos de memória e logs antes de salvar, evitando que chaves de API, segredos da Shopee ou tokens do Threads entrem no histórico do Git. As ações do GitHub Actions continuam fixadas por hash completo SHA, garantindo integridade.

## Achados da Auditoria

### 1. Ausência da marcação #publi em respostas a comentários com links
* **Arquivo e linha:** `bot.py` (linha 2458)
* **Gravidade:** Média
* **Por que importa:** Quando um usuário pede o link de um produto nos comentários, o robô responde enviando o link sem a hashtag `#publi`. As diretrizes da Meta e do Threads exigem a identificação clara de links comerciais e de afiliados. O envio recorrente de links de afiliados sem a sinalização de publicidade pode levar a restrições de alcance ou bloqueio da conta por violação das políticas da plataforma.
* **Correção sugerida:** Manter a identificação de conteúdo comercial com a hashtag `#publi` ou `#afiliado` também nas respostas enviadas aos usuários nos comentários.

### 2. Versionamento de logs de execução do gerador de artes no repositório
* **Arquivo e linha:** `.github/workflows/artes-ia.yml` (linha 39) e `stitch.py` (linhas 296 e 343)
* **Gravidade:** Baixa
* **Por que importa:** O arquivo `carrosseis/stitch_log.json` continua sendo salvo e versionado no Git a cada execução da geração de imagens. Embora a chave de API seja verificada e protegida antes de salvar, o armazenamento constante desses arquivos de log aumenta o volume do histórico do Git com dados operacionais temporários.
* **Correção sugerida:** Incluir o arquivo `carrosseis/stitch_log.json` no arquivo `.gitignore` para evitar o acúmulo de logs operacionais no histórico do repositório.
